# dev-retro — 把 session 里的错误与绕路，变成 repo 的改进

## 定位

agent 没有跨 session 记忆，同样的错、同样的绕路会在每个 session 里重来。本 skill 由人手动
调用，agent 从本次轨迹里筛出两类东西：

- **错误** — agent 做错后被纠正的事。纠正者可能是 agent 自己（命令失败后换了做法、改完又改回），
  也可能是人（任务中的"不对，应该是…"，或 dev-retro 过程中对分析结论的纠正）。人的纠正里
  往往带着 agent 看不到的背景，价值最高。
- **长链短知识** — agent 最终成功了，但从提问到答案走了很长的探索链，而答案只有一两句话
  （典型：repo 里有个工具能直接做这件事，agent 是从底层机制一路反推才找到它的）。
  这类没有任何报错，agent 不会把它当问题。

跨 session 的**重复**不在这两类里：agent 感知不到"这是第 N 次了"，不要求它识别——那是人在
提示里带进来的信息。agent 对每条筛出的东西回答两个问题：**为什么我会这样做**，以及
**改 repo 的哪里能让下一个 session 不再这样**。

调用时附带的文字就是人类提示。它常常包含 agent 看不到的东西：为什么这么做是错的、这块
代码的历史、没写下来的团队约定。它是本 skill 最重要的输入。

产出是一组落到 repo 具体位置、可逐条批准的改动提议——不是一份反思报告。

### 明确不做的事

- **不自行改文件** — 提议，等用户逐条选择后再执行
- **不给发现打分** — 严重度、置信度、节省步数这类数字在实践中总是同一个值，从未影响过决策
- **不给发现贴类型标签** — 按问题本身描述，标签不改变结论；唯一要分类的是「归属」（往哪放）
- **不把"再加一条规则"当默认答案** — 见「归属」
- **不写个人偏好进 repo** — 那属于宿主的个人记忆（机器本地），repo 只放团队共享的知识

---

## 输入：三样东西，按可信度排序

1. **人类提示。** 它带来三样 agent 自己拿不到的东西：跨 session 的重复观察、没写下来的背景、
   以及对本次分析结论的纠正——最后这种直接就是要落进 repo 的知识。没有外部信号时，agent 对
   自己失败原因的自诊断经常自信而错误（研究和我们自己的历史记录都是这样），所以没有提示时
   明说这一点，只报告能从轨迹里数出来的信号，不推测动机。

2. **执行轨迹。** context 里的记忆经过 compaction 后失真最大的恰好是失败的尝试。回读磁盘上的
   原始转录（路径见文末表格，取最近修改且工作目录匹配的那份），用脚本找信号，不凭印象回忆：
   错误的信号是命令失败后换了做法、同一文件改了又改回、用户消息里的纠正；长链的信号是从提问到
   第一个有效动作之间经过了多少次搜索和阅读——链很长、结论很短，就是加速路径。

3. **repo 现状。** 提议前读一遍你要改的文件：确认问题此刻仍然成立，确认要加的东西不是已经存在
   只是没被找到——后者的修法完全不同。

---

## 分析：先问为什么，再谈修法

一个错误或一条长链的背后一般是下面之一。修法取决于是哪一种，所以先判断，再提议：

| agent 为什么会这样 | 修法方向 |
|---|---|
| 信息不存在 | 在归属正确的位置补上 |
| 信息是错的 / 过时的 | 改正源头，删掉复制品 |
| 信息或工具存在但到不了：没索引、埋在长文件里、名字对不上、入口只能从机制反推 | 建从任务类型指向位置/工具的指针、改名、拆分 |
| 信息到了但指令没有约束力：如"优先加载"混在关键词匹配流程里 | 改机制，不是再抄一遍内容 |
| 代码结构逼着探索：隐式依赖、散落的映射表、魔法值 | 改代码：注释、集中、命名 |
| 人类提示里的背景是隐性的团队知识 | 把背景写到它该在的地方，让下次不需要人来提示 |

## 归属：这条真相归谁所有

按偏好排序，越靠前越好。往后退一级需要理由。

1. **源头本身** — 代码注释、命名、结构调整、把散落的常量集中。能让人和 agent 直接从代码读到的，
   不要另写散文；散文会和代码脱节。
2. **索引与指针** — 就地一行"改 X 先看 Y"，或**错题集**：一个按问题类型命名文件的目录
   （repo 已有同类目录就用它，没有就建 `docs/knowledge/`），每个文件只回答"解决这类问题先看哪里、
   坑在哪里"，用路径引用。文件名就是索引，所以要用任务或症状的说法命名——agent 带着任务来，
   不是带着模块名来。适用于知识跨多个位置、或从任务/症状出发而不是从某个文件出发的情况，
   这时一处注释不够。要让它被拉取，指令文件里留一行指向这个目录。
3. **skill** — 多步流程、方法论。教"怎么找"，不记"是什么"：实现会变，方法论稳定。
4. **常驻指令文件**（`CLAUDE.md` / `AGENTS.md` / 路径级 rules）— 只放两类东西：不可从代码推导的
   事实；推导代价远高于一行指针的入口（工具、猜不到的命令）。每加一行都会稀释已有的行，
   所以加一行就要删一行或改成指针，净长度不增。
5. **hook** — 必须每次都发生、不能指望模型记得的行为。散文规则是请求，不是保证。
6. **不写** — 只在本次 session 成立的一次性情况。

三条写法约束，来自过去被反复违反的记录：

- **引用位置，不复制值。** 写 `common/enum/enum.go` 和解码方法，不把映射表抄进文档。
- **一个事实只在一处。** 跨文件用路径引用，不复述。
- **单次发现带着适用条件记录。** 升级为常驻规则需要人类确认、或同一问题再次出现。
  把条件抽象掉，是记忆变坏的主要方式。

一个加速路径的落法示例：agent 经 反射 → HTTP 暴露 → URL 搜索 → 工具代码 才发现 `tools/xxx`
能直接读写运行中进程的数据。落法是三件事：`tools/xxx` 的代码或 README 补用法注释（源头）；
错题集里建 `docs/knowledge/运行中进程数据读写.md`，内容只有"用 `tools/xxx`，用法见其注释，
接口见 `<注册接口的文件>`"（指针）；接口列表不抄进任何文档。

---

## 输出

给用户一组编号提议。每条写清：

- 观察到的信号（具体时刻或数字），以及它和人类提示的对应
- 为什么会这样（上表的哪一行）
- 目标文件 + 具体改动（diff 或原文）；动常驻指令文件时写明净长度变化
- 一条只改一个点，方便归因和回滚

用户选择后只执行被选中的。没选的、以及"发现了但想不出好改法"的，连同人类提示一起写进一份
短记录（如 `docs/retrospective/YYYY-MM-DD-<title>.md`，自由格式，不覆盖已有文件；这是收尾时
唯一不经逐条批准、直接写入的文件）。它是原始
记录，和错题集分工不同：错题集只写"现在该怎么走"，记录保留"当时发生了什么、否决了什么"，
用来防止重提已否决的方案，以及在几次记录之后看出真正反复出现的问题。

| | Claude Code | Codex |
|---|---|---|
| 人类提示如何到达 | `/dev-retro <提示>`，随消息注入 | `$dev-retro <提示>`，随同一条消息到达 |
| 原始转录 | `~/.claude/projects/<项目路径转义>/<session-id>.jsonl`；`type` 为 `user`/`assistant`，工具调用在 `assistant` 的 `message.content` 里 | `~/.codex/sessions/YYYY/MM/DD/rollout-<时间>-<id>.jsonl`；工具调用是 `response_item` 里的 `function_call` / `custom_tool_call` / `local_shell_call`，靠 `call_id` 对应输出；`compacted` 记录之前的内容仍完整保留 |
| 常驻指令文件 | `CLAUDE.md`、`.claude/rules/*.md`（可按 `paths` 限定） | `AGENTS.md`（按目录层级生效，没有路径级 rules；`.codex/rules/` 是命令权限规则，不是指令） |

| 仅手动调用 | frontmatter `disable-model-invocation: true` | `agents/openai.yaml` 的 `policy.allow_implicit_invocation: false`（Codex 忽略未知 frontmatter 字段） |
